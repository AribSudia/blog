أحياناً تعرف **بالضبط** ما تريد.

لا تحتاج شيئاً يكتشف المهام — تحتاج شيئاً **يُنجزها**.

هذا ما بُني له `/arib-build`.

---

## الفكرة بجملة واحدة

أعطه هدفاً محدداً — فيُفكّكه، يوزّع أجزاءه على المتخصصين **بالتوازي**، يجمع نتائجهم، ويُمرّره بوابة الدمج.

```
decompose → dispatch specialists in parallel → integrate → reconcile → merge gate
```

الفرق عن أي skill آخر: **الفريق كله يعمل في وقت واحد**، لا جولة بعد جولة.

---

## الحلقة التي يعمل عليها

```
┌─────────────────────────────────────────────┐
│              /arib-build <goal>              │
│                                             │
│  1. DECOMPOSE  → يُفكّك الهدف إلى مهام      │
│       ↓                                     │
│  2. DISPATCH   → يُوزّع على متخصصين بالتوازي│
│       ↓ ↓ ↓                                 │
│   Architect  Reviewer  Tester  Security…    │
│       ↓ ↓ ↓                                 │
│  3. INTEGRATE  → يجمع النتائج               │
│       ↓                                     │
│  4. RECONCILE  → يُراجع ويتحقق              │
│       ↓                                     │
│  5. MERGE GATE → بوابة قبل الدمج            │
└─────────────────────────────────────────────┘
```

المتخصصون لا ينتظرون بعضهم — يعملون **معاً** على أجزاء الهدف، مثل فريق هندسي حقيقي.

---

## المقارنة مع `/arib-engine`

هما أخوان — لا بديلان. كل واحد مصمّم لموقف مختلف:

| | `/arib-engine` | `/arib-build` |
|--|---------------|---------------|
| **متى تستخدمه** | لا تعرف ما يحتاجه المشروع بعد | تعرف الهدف بالضبط |
| **يكتشف العمل؟** | ✅ نعم — adversarial find→refute→confirm | ❌ أنت تحدده |
| **الإيقاع** | مستمر حتى يجتاز اختبار الإغلاق | جولة واحدة حتى الهدف |
| **"هل انتهينا؟"** | يُقرّر الدليل | يُقرّر الهدف المُحدّد |
| **التوزيع** | دورة واحدة في كل جولة | متخصصون بالتوازي |
| **المناسب لـ** | مشكلة مفتوحة / حملة مستمرة | تسليم هندسي محدّد |
| **الضبط مع `/loop`** | ✅ الطريقة الطبيعية | ❌ غير مصمّم لها |
| **حجم الـ skill** | 300 سطر | 70 سطر — مُركّز |

## من يُنسّق؟

`/arib-build` يُطلق **الـ engineer-manager** — المايسترو الذي يعرف كيف يُوزّع العمل على المتخصصين الـ 17 في CCM ويجمع نتائجهم في تسليم واحد متماسك.

الـ engine يُدير نفسه. البيلد يُدير فريقاً.

---

## حالات الاستخدام

```bash
# بناء ميزة كاملة بالمواصفات
/arib-build "payment gateway with Tap, idempotency, and audit trail"

# إعادة بناء وحدة موجودة
/arib-build "refactor auth module to support OAuth2 + API keys"

# تسليم تقني محدد
/arib-build "add RTL support to the checkout flow with full a11y"
```

في كل حالة: يُفكّك، يُوزّع، يجمع، يُغلق. **واضح من البداية، مُكتمل في النهاية**.

---

## متى تختار أيهما؟

**استخدم `/arib-build`** حين:
- الهدف محدّد بوضوح
- تريد تسليماً في جولة واحدة
- تعمل مع فريق متخصصين بالتوازي

**استخدم `/arib-engine`** حين:
- تحتاج من يكتشف ما يجب عمله
- المشكلة مفتوحة ("صلّب الـ codebase", "حسّن الأداء")
- تريد حملة مستمرة بـ `/loop`

**الجمع بينهما**: اجعل الـ engine يكتشف أولاً — ثم أطلق البيلد على كل هدف يُحدّده.
